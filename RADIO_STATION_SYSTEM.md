# 📻 Radio Station Systeem - Complete Documentatie

## 📊 Overzicht

Een complete radio station waar alle players dezelfde muziek tegelijk afspelen, gestuurd door een backend scheduler die elke minuut checkt welke track moet spelen.

---

## 🎯 Drie Hoofdonderdelen

### 1. Backend Scheduler (AWS Lambda) 📡

**Lambda:** `radio-scheduler`  
**Trigger:** EventBridge (rate: 1 minute)  
**Locatie:** `/amplify/functions/radio-scheduler/`

#### Functionaliteit:
```
⏰ Draait elke minuut
   ↓
📅 Load Schedule uit DynamoDB
   - Bepaal active slot (bijv: 21:00-22:00)
   - Haal playlist ID (bijv: TECHNO)
   ↓
🎵 Load Playlist + Tracks
   - Parse JSON tracks array
   - Calculate elapsed time in slot
   ↓
🎯 Calculate Current + Next Track
   - Welke track speelt NU?
   - Wanneer start VOLGENDE track?
   ↓
⏱️ Check Time Window (5 seconden)
   Als timeUntilNext <= 5 sec:
   ↓
📡 BROADCAST via IoT
   Topic: radio/station/current-track
   Message: LOAD_AND_SCHEDULE command
```

#### Code Structuur:
```typescript
// handler.ts
- loadSchedule() → DynamoDB scan
- findActiveSlot() → Time-based matching
- loadPlaylist() → Get playlist + tracks
- calculateTrackTiming() → Current/next track
- publishToIoT() → Broadcast to players
```

#### Environment Variables:
```
SCHEDULE_TABLE_NAME
PLAYLIST_TABLE_NAME
TRACK_TABLE_NAME
IOT_ENDPOINT
```

#### Permissions:
- DynamoDB Read: Schedule, Playlist, Track
- IoT Publish: radio/station/*

### 2. Frontend Player (React) 🎵

**Component:** `Players.tsx`  
**Locatie:** `/apps/web/src/pages/devices/`

#### Twee Modi:

##### Station Mode (IoT-Driven):
```
📻 Subscribe: radio/station/current-track
   ↓
📥 Receive: LOAD_AND_SCHEDULE command
   {
     track: { id, title, fileUrl, ... },
     timing: { startAt, bufferSeconds: 5 }
   }
   ↓
📥 Load Track Assets (5 sec buffer!)
   - Get S3 presigned URLs
   - Load MP3 in <audio> element
   - Load cover art + waveform
   ↓
⏰ Calculate Delay
   delay = startAt - now
   ↓
⏱️ setTimeout(() => play(), delay)
   ↓
🎵 START PLAYBACK at exact time!
```

##### Manual Mode (User Control):
```
🖱️ Click LOAD → Load scheduled track
🖱️ Click PLAY → Play immediately (no delay!)
⏸️ Click PAUSE → Pause + save position
⏹️ Click STOP → Stop + reset
```

#### State Management:
```typescript
// Station state
stationMode: 'manual' | 'station'
scheduledPlayback: NodeJS.Timeout | null

// PlayerState (persistent)
playerStateId: string | null
isRestoringState: boolean
```

#### Key Functions:
```typescript
- setupStationSubscription() → IoT subscription
- loadTrackIntoPlayer() → Load from S3
- handleLoad() → Manual load
- handlePlay() → Direct playback
- savePlayerState() → Persist to DynamoDB
```

### 3. Player State Persistence (DynamoDB) 💾

**Model:** `PlayerState`  
**Table:** Auto-generated by Amplify

#### Schema:
```typescript
{
  id: string (PK)
  playerId: string // "player-main-001"
  
  // Track Info
  currentTrackId: string
  currentTrackTitle: string
  currentTrackArtist: string
  currentPlaylistId: string
  
  // Playback State
  status: 'playing' | 'paused' | 'stopped' | 'idle'
  lastPosition: number // seconds
  duration: number
  volume: number
  
  // Settings
  autoPlayEnabled: boolean
  
  // Schedule Context
  currentScheduleSlotId: string
  currentScheduleSlotName: string
  
  // Timestamps
  lastActive: datetime
  lastUpdated: datetime
}
```

#### Save Triggers:
- **LOAD** → Save track info, status: stopped
- **PAUSE** → Save position
- **STOP** → Reset position to 0
- **5-minute checkpoint** → Update position during playback
- **Page unload** → Save before close

#### Restore Flow:
```
Page Load:
1. getPlayerState(playerId)
2. If status === 'paused' && lastPosition > 0:
   - Load track
   - Seek to lastPosition
   - Keep paused state
3. Restore volume + settings
```

## 📡 IoT Topics

### Station Broadcast (Backend → All Players):
```
radio/station/current-track
```
**Publisher:** Backend Lambda (radio-scheduler)  
**Subscribers:** All players  
**QoS:** 1 (at least once delivery)

**Message Format:**
```json
{
  "command": "LOAD_AND_SCHEDULE",
  "mode": "station",
  "track": { /* full track object */ },
  "timing": {
    "startAt": "ISO timestamp",
    "loadBy": "ISO timestamp",
    "bufferSeconds": 5
  },
  "playlist": { "id": "...", "name": "..." },
  "slot": { "id": "...", "name": "...", "time": "..." },
  "timestamp": "ISO timestamp"
}
```

### Player Commands (Manual Control):
```
radio/player/{playerId}/command
```
**Example:** `radio/player/player-main-001/command`

### Player State Updates:
```
radio/player/{playerId}/state
```
Real-time status broadcasts (playing, paused, position, etc.)

## 💰 Cost Analysis

### EventBridge:
- 1 million invocations/month: FREE
- We use: ~43,800/month (1 per minute)
- **Cost: $0**

### Lambda Invocations:
- First 1M requests: FREE
- Duration: ~200ms per run
- **Cost: $0** (under free tier)

### DynamoDB:
- Reads: ~50/minute = 2.16M/month
- On-demand pricing: $0.25 per 1M reads
- **Cost: ~$0.54/month**

### IoT Core:
- Messages: ~10-20 per track change
- ~500 messages/day = 15k/month
- First 1B messages: FREE
- **Cost: $0** (under free tier)

### PlayerState Writes:
- ~50 writes/day/player
- 10 players = 500 writes/day = 15k/month
- On-demand: $1.25 per 1M writes
- **Cost: ~$0.02/month**

**Total: ~$0.60/month** 💰✅

## 🐛 Troubleshooting

### Lambda Not Triggering:
1. Check EventBridge rule:
   ```bash
   aws events list-rules --name-prefix RadioScheduler
   ```
2. Check Lambda permissions
3. View CloudWatch Logs

### Frontend Not Receiving:
1. Check IoT subscription in console
2. Verify topic name: `radio/station/current-track`
3. Check IoT Core metrics in AWS Console

### Players Not Syncing:
1. Check system clocks (NTP sync)
2. Verify 5-second buffer is enough
3. Check network latency
4. Review console logs for timing info

### PlayerState Not Saving:
1. Check DynamoDB table exists
2. Verify permissions (Cognito → DynamoDB)
3. Check `playerStateId` is set
4. Review console for save errors
